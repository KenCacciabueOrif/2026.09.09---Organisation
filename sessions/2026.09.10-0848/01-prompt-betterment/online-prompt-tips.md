# Online prompt tips — Cycle 9 (WorkSpace-only Continuity)

Actionable prompting practices for a **fail-closed remaining-item** program cycle (research hazards → defer unless cleared or dedicated git-strategy Continuity). Sources checked 2026-09-10.

1. **Separate Continuity Choose from irreversible action** — Treat scope/Continuity answers as planning locks only; require a later explicit approval before any folder move (`fs_mutation`). Cursor Plan Mode: clarify → plan → wait for approval before building.  
   Source: https://cursor.com/blog/agent-best-practices

2. **Ask a short upfront pack before research** — 1–2 targeted questions on path (defer vs git-strategy) and Continuity carry beat re-asking full first-batch packs; mirrors “Stage 1 clarification before jumping in.”  
   Source: https://forum.cursor.com/t/feature-linear-integration-2-stage-agent-clarification-before-jumping-into-implementation/165645

3. **Consent as scoped transaction preview** — Each option should say what “yes” commits to *and* what happens if the user declines (e.g. stay fail-closed / docs-only defer). Prefer concrete outcome language over vague “allow agents.”  
   Source: https://supervised.online/designing-consent-first-agents-technical-patterns-for-privac

4. **Granular authorization, not broad grants** — Continuity “carry layout / opaque .env / SSH path-only” is not blanket permission to relocate `WorkSpace`; keep purpose and scope versioned in session notes.  
   Source: https://aicode.cloud/consent-preserving-agentic-assistants-technical-patterns-for

5. **Specific, verifiable acceptance criteria** — Encode “never force-move,” “never mark Multi-experiment Complete while WorkSpace remains,” and “plan gate only if `fs_mutation`” as checkable AC — not soft prose.  
   Source: https://cursor.com/blog/agent-best-practices

6. **Prefer reversible defaults when the user says Choose** — Default A = research hazards then defer (docs/INDEX honesty) over irreversible corpus moves; only opt into git-strategy planning when explicitly chosen.  
   Source: https://cursor.com/blog/agent-best-practices (specific prompts + plan-before-build)

7. **Fail closed on ambiguity** — If nested-git / remotes / locks look unsafe, stop that item and document rather than guessing a move; encode this in the refined prompt so later phases cannot invent a force-move.  
   Source: https://cursor.com/blog/agent-best-practices (verifiable goals / don’t compound bad plans)
